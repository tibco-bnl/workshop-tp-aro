# Release Notes - v1.18.0

**Release Date:** June 2026
**TIBCO Platform Control Plane Version:** 1.18.0
**Platform:** Azure Red Hat OpenShift (ARO)
**Status:** Current release

## Overview

This release updates the ARO workshop documentation for TIBCO Platform Control Plane 1.18.0. It carries forward the 1.17.0 simplified DNS model and adds 1.18.0 Control Plane features that affect ARO operators: Gateway API controller support, namespace-level RBAC, Alert Audit Trail, Console-managed email server configuration, and Developer Hub self-service flows.

Official documentation:

- [TIBCO Platform Control Plane 1.18.0 Documentation](https://docs.tibco.com/pub/platform-cp/1.18.0/doc/html/Default.htm)
- [Official 1.18.0 New Features](https://docs.tibco.com/pub/platform-cp/1.18.0/doc/html/Release-Notes/new-features.htm)
- [Official 1.18.0 Known Issues](https://docs.tibco.com/pub/platform-cp/1.18.0/doc/html/Release-Notes/known-issues.htm)

## What's New in v1.18.0

### TIBCO Control Plane

#### Gateway API Controller Support

Gateway API Controller is supported for Control Plane and Control Tower data planes. On ARO, OpenShift Routes remain the primary ingress mechanism. Gateway API resources (`Gateway`, `HTTPRoute`) can be evaluated where the OpenShift Gateway API is available in the cluster, or BW5/BW6/Flogo capabilities can select the `Other Gateway API Controller` option when a compatible third-party Gateway API controller is already installed.

#### Namespace-Level RBAC for Data Planes

Kubernetes namespaces are now Data Plane-level resources managed under Data Plane Configuration > Resources. Application Manager and Application Viewer role assignment screens include Capability and Namespace selectors for granular access control.

#### Email Server Configuration in Platform Console

Email server configuration moved from `tibco-cp-base` chart values to the TIBCO Platform Console UI. Configure SMTP from the Console after installation or upgrade. Remove deprecated email Helm values before upgrading to 1.18.0.

Deprecated values removed by the 1.18 upgrade assistant include:

- `global.external.emailServerType`
- `global.external.fromAndReplyToEmailAddress`
- `global.external.cronJobReportsEmailAlias`
- `global.external.platformEmailNotificationCcAddresses`
- `global.external.emailServer`

#### Alert Viewer and Alerts Audit Trail

The UI includes an Alerts Audit Trail page that records system health and rule performance events.

#### Developer Hub Self-Service Flows

Developer Hub self-service flows provide reusable building blocks for platform automation through customizable templates and platform APIs.

### Capability Updates

- BW5 and BW6 Containers add Traefik Gateway API support and an `Other` Gateway API controller option.
- Flogo adds Traefik Gateway API support, NetScaler Gateway support at the Data Plane level, and namespace-level RBAC enforcement.
- Hawk 1.18.12 charts are available for the 1.18 release stream.
- The open source `bw5toCE` automation tool is available to help migrate BW5 Administrator applications to TIBCO Platform.

## ARO-Specific Considerations

### Simplified DNS Continues

The simplified DNS model remains applicable in 1.18.0. ARO installations should prefer one Control Plane base domain such as `platform.ocp-tibco.azure.example.com`, with Platform Console at `admin.platform.ocp-tibco.azure.example.com` and subscriptions at `<hostPrefix>.platform.ocp-tibco.azure.example.com`. In Helm values, set `global.external.dnsDomain` and `global.external.dnsTunnelDomain` to the same base domain. The `hybrid-proxy` chart routes tunnel traffic through `/infra/tunnel` on that shared domain.

Use one Azure DNS wildcard record and one wildcard TLS certificate for `*.platform.ocp-tibco.azure.example.com`. Keep separate `cp1-my` and `cp1-tunnel` domains only for legacy or explicitly separated deployments.

### Gateway API on OpenShift

OpenShift Routes remain the primary and recommended ingress mechanism for ARO deployments. OpenShift 4.14+ includes the OpenShift Gateway API (via the `gateway.networking.k8s.io` CRDs). If your ARO cluster has the Gateway API installed, BW5, BW6, and Flogo capabilities can evaluate Gateway API endpoint exposure by selecting the `Other Gateway API Controller` type during provisioning.

Keep OpenShift Route-based ingress for existing routes unless you explicitly plan to migrate endpoint exposure to Gateway API resources.

### Email Server Moves to Console

Do not pass email server settings in 1.18.0 Helm values. After installation or upgrade, configure your email provider in the TIBCO Platform Console. For ARO workshop environments that use MailDev, keep the MailDev service running and configure the Console with:

| Field | Value |
|-------|-------|
| SMTP host | `development-mailserver.tibco-ext.svc.cluster.local` |
| SMTP port | `1025` |
| TLS | Disabled |

The `global.tibco.networkPolicy.emailServer` block in `tibco-cp-base` values controls optional egress NetworkPolicy creation only — it does not configure the email provider. Leave its CIDR empty unless you need an explicit allow rule.

### SCC Compatibility

There are no breaking Security Context Constraints changes in 1.18.0. The `tp-scc` grants on service accounts in the Control Plane and Data Plane namespaces remain required before Helm installs. SCC bindings from 1.17.0 carry forward without modification.

### Namespace-Level RBAC

Before upgrading shared ARO clusters, inventory application namespaces and review Application Manager/Application Viewer assignments in the TIBCO Platform Console. After upgrade, users may need explicit namespace grants to deploy or view applications. OpenShift RBAC works alongside the TIBCO Platform namespace-level RBAC model.

## Upgrade Path from v1.17.0

1. Back up Helm values, Kubernetes secrets, and PostgreSQL data.
2. Update the `tibco-platform` Helm repository.
3. Remove deprecated email Helm values from `tibco-cp-base` values.
4. Upgrade Control Plane base and infrastructure charts to 1.18.0-compatible versions.
5. Upgrade Data Plane components and capability charts.
6. Configure email server from the TIBCO Platform Console.
7. Review namespace-level RBAC assignments.
8. Validate Gateway API endpoint behavior if used.
9. Confirm Alerts Audit Trail events are recorded.

## Upgrade Path from v1.16.0

Upgrade to 1.17.0 first, then upgrade to 1.18.0:

1. Follow [v1.16.0 to v1.17.0 upgrade notes](./v1.17.0#upgrade-path).
2. Apply the v1.18.0 upgrade path above.

## Known Issues to Review

- Existing 1.17.0 Data Planes can show incorrect Integration Summary and Application Instance card data after Control Plane upgrade until the Data Plane is upgraded to 1.18.0.
- Traces and application service metrics have known limitations in some Control Tower data plane environments.
- BW6 Swagger tester behavior can require BW6 capability and application upgrades when changing endpoint visibility through Gateway API.
- Flogo capability provisioning can fail if users navigate backward and forward in early wizard steps; restart the provisioning flow as a workaround.

Review the complete official list before production upgrades: [Official 1.18.0 Known Issues](https://docs.tibco.com/pub/platform-cp/1.18.0/doc/html/Release-Notes/known-issues.htm).
