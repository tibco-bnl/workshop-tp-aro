# Release Notes - v1.20.0

**Release Date:** August 2026 (official documentation published August 31, 2026)
**TIBCO Platform Control Plane Version:** 1.20.0
**Platform:** Azure Red Hat OpenShift (ARO)
**Status:** Current release
**Workshop documentation updated:** September 21, 2026

## Overview

This release updates the ARO workshop documentation for TIBCO Platform Control Plane 1.20.0. It also catches up on the intermediate 1.19.0 release, which is a mandatory hop when upgrading from 1.18.0 (see [v1.19.0 release notes](./v1.19.0)).

1.20.0 is a small Control Plane release: Control Plane rollback, OTLP exporters with custom headers, dedicated Kubernetes Jobs for Flogo builds, the Developer Hub MCP Catalog, and MCP Hub (Preview, TIBCO Operated Control Plane only). For self-hosted ARO deployments the most important operator-facing changes are in the `tibco-cp-base` chart: a new `global.tibco.disabledInfraCapabilities` value, a changed `otel-collector` default, and (since 1.19.0) the removal of `createDeprecatedPolicies` and the fixed hybrid-proxy Gateway API route. There are no SCC changes.

## What's New in v1.20.0

### TIBCO Control Plane

#### Control Plane Rollback

If an upgrade fails, the Control Plane can be rolled back to the version it was upgraded from. With `global.tibco.manageDbSchema: true` (workshop default) a single `helm rollback <release> <revision> -n <namespace> --wait` reverts both the release and the database schema. With `manageDbSchema: false`, first run `postgres-helper.bash rollbackDbSchema <chart-version>` from the `tp-helm-charts` database scripts (port-forward the PostgreSQL pod in `tibco-ext`). TIBCO recommends rolling back the Control Plane before upgrading any Data Plane or capability.

#### OTLP Exporter with Custom Headers

OTLP (http and grpc) exporters and query services for logs, metrics, and traces accept custom header key/value pairs. The secondary exporter supports OTLP only.

#### MCP Hub (Preview)

MCP Hub is the central console for Model Context Protocol infrastructure with a built-in MCP Gateway (guardrails, plugins, virtual tools, virtual servers). It is available in TIBCO Operated Control Plane only. The gateway runtime is the new `tp-mcp-gateway` Data Plane chart (Full mode PostgreSQL plus Redis, Lite mode SQLite). Self-hosted Control Planes on ARO cannot use MCP Hub in 1.20.0.

### Capability Updates

- **Flogo:** application builds run in dedicated Kubernetes Jobs with their own CPU, memory, queue, and timeout settings (`FLOGO_APP_BUILD_CPU_REQUEST`, `FLOGO_APP_BUILD_CPU_LIMIT`, `FLOGO_APP_BUILD_MEMORY_REQUEST`, `FLOGO_APP_BUILD_MEMORY_LIMIT`, `FLOGO_APP_BUILD_TIMEOUT_SECONDS`, `FLOGO_APP_BUILD_MAX_QUEUED_SECONDS`). On ARO, build Jobs run under the same `tp-scc` grants as the Flogo provisioner service account.
- **Developer Hub:** MCP Catalog registers MCP servers as Backstage API entities (`spec.type: mcp-server`); requires Backstage 1.51.0+ (shipped in 1.19.0) and Advanced navigation mode.
- **BW5 and Adapters (Control Tower):** bulk suspend/resume of process starters, richer Active Processes and Locks tabs.
- **Messaging:** no 1.20.0 EMS or ActiveSpaces charts were published; the latest messaging charts remain 1.19.23. The official compatibility matrix lists EMS 1.19.0 as the latest row.

### Deprecated and Removed

- NGINX Ingress Controller support is removed (wording unchanged since 1.18.0). On ARO the OpenShift Router remains the supported ingress (`ocp-v4.0`).

## Chart Changes That Affect ARO Values Files

From the `tibco-cp-base` chart source in `tp-helm-charts` (tags `tibco-cp-base-1.18.0`, `-1.19.0`, `-1.20.0`):

| Value | 1.18.0 | 1.19.0 | 1.20.0 | Action |
|-------|--------|--------|--------|--------|
| `global.tibco.networkPolicy.createDeprecatedPolicies` | `true` | removed | removed | Delete from `tibco-cp-base-*.yaml` before upgrading to 1.19.0 or later |
| `otel-collector.enabled` (chart default) | `false` | `true` | `false` | Set explicitly. The 1.20.0 chart disables it so a log server is not a prerequisite; enable only with a reachable Elasticsearch/OpenSearch log server |
| `global.tibco.disabledInfraCapabilities` | n/a | n/a | `[MFTADAPTER]` | New. Capability IDs removed from every Data Plane type's mandatory infra capability list. MFT off by default; set `[]` to enable all |
| `hybrid-proxy.gatewayRoute` HTTPRoute rules | `/` only (PCP-21362) | `/infra/tunnel` always; `/` only when `dnsDomain != dnsTunnelDomain` | same | Simplified DNS with Gateway API no longer needs hostname separation |
| Fluent Bit sidecar tag | 5.0.6 | 5.0.9 | 5.1.0 | Informational |

`scripts/1.20.0/upgrade.sh` in `tp-helm-charts` performs no value transformations; it validates that the release is `deployed` at `app_version` 1.19.0, copies values, and runs `helm upgrade` to chart 1.20.0.

## ARO-Specific Considerations

### SCC Compatibility

There are no Security Context Constraints changes in 1.19.0 or 1.20.0. The `tp-scc` grants for the Control Plane and Data Plane service accounts remain required before Helm installs and carry forward unchanged. New capability service accounts (for example the Infra MCP Server or Flogo build Jobs) need the usual `oc adm policy add-scc-to-user tp-scc` grant.

### Simplified DNS and Gateway API

OpenShift Routes remain the primary ingress mechanism. If you evaluate Gateway API, note that since `tibco-cp-base` 1.19.0 the `hybrid-proxy` HTTPRoute renders `PathPrefix: /infra/tunnel` itself and omits the catch-all `/` when `dnsDomain == dnsTunnelDomain`, so both `hybrid-proxy` and `router-operator` can share the `*.<base-domain>` hostname on one Gateway. The chart never consumed a `gatewayRoute.rules` value; remove explicit rules left over from the 1.18 workaround.

### otel-collector and the Log Server

The workshop `tibco-cp-base-*.yaml` files set `otel-collector.enabled: true` explicitly. If you rely on the chart default instead, it is `false` in 1.20.0. Enable it only when an Elasticsearch or OpenSearch log server is reachable from the Control Plane namespace.

### Developer Hub Storage

Known issue PLTDX-1343: with Azure Files (`azure-files-sc`) the Developer Hub PostgreSQL pod fails on `chmod`. Use the Azure Disk class (`managed-premium` in this workshop) for Developer Hub database storage.

### Email with MailDev

Unchanged since 1.18.0: keep MailDev running and enter `development-mailserver.tibco-ext.svc.cluster.local:1025` in the Platform Console. Do not add email Helm values.

### Infra MCP Server and MCP Gateway RBAC

`dp-configure-namespace` 1.19.10 and later create RBAC for the Infra MCP Server and MCP Gateway capabilities (`rbac.infraMcp`, `rbac.mcpGateway`, `rbac.springboot`, default `true`). Cluster-scoped diagnostics require `rbac.infraMcpClusterScoped=true`. TESSA, which consumes the Infra MCP Server, is only available on TIBCO Operated Control Plane (US region).

## Upgrade Path from v1.19.0

1. Back up Helm values, `session-keys` and `cporch-encryption-secret`, and PostgreSQL data. Record `helm history tibco-cp-base -n ${CP_INSTANCE_ID}-ns`.
2. Verify `tp-scc` grants are still in place for `${CP_INSTANCE_ID}-sa` and `default`.
3. Update the `tibco-platform` Helm repository.
4. Confirm `createDeprecatedPolicies` is absent and set `otel-collector.enabled` and `global.tibco.disabledInfraCapabilities` intentionally.
5. Upgrade `tibco-cp-base` to 1.20.0 or run `scripts/1.20.0/upgrade.sh` from `tp-helm-charts`.
6. Upgrade capability charts to 1.20.0 (`tibco-cp-bw`, `tibco-cp-flogo`, `tibco-cp-devhub`; `tibco-cp-hawk --version '1.20.*'`). Leave `tibco-cp-messaging` at 1.19.23.
7. Upgrade Data Plane infrastructure from the Control Plane UI (`dp-configure-namespace` 1.20.0, `dp-core-infrastructure` 1.20.3), then capabilities. The official matrix requires DP 1.20.0 and CP 1.20.0 for Flogo, BW5CE, BW6CE, and Developer Hub 1.20.0.
8. Validate with `scripts/verify-release.sh` from `tp-helm-charts` (`CHECK_RELEASE_FOLDER=control-plane`, `CHECK_RELEASE_VERSION=1.20.0`).

## Upgrade Path from v1.18.0

Direct 1.18.0 to 1.20.0 upgrades are not supported by the upgrade assistants (`scripts/1.19.0/upgrade.sh` requires `app_version` 1.18.0, `scripts/1.20.0/upgrade.sh` requires 1.19.0). Upgrade to 1.19.0 first:

1. Follow the [v1.19.0 upgrade path](./v1.19.0#upgrade-path-from-v1180).
2. Apply the v1.20.0 upgrade path above.

Alternatively use the sequential master script documented in `scripts/MASTER-UPGRADE-README.md` in `tp-helm-charts`.

## Known Issues to Review

New in 1.20.0:

- **PCP-23615:** after upgrading to 1.20.0, deleting a Data Plane's observability configuration fails. No workaround.
- **FLOGO-18866:** WebSocket application public endpoint URLs are shown with `https://`; use `wss://`.

Carried over and relevant to ARO users:

- **PCP-20148:** traces recorded before the Jaeger v2 move (1.19.0) appear as red dots.
- **PCP-19687:** cards show wrong data for Data Planes still on the previous release until they are upgraded.
- **PCP-17037 / PCP-9344 / BWCE-8521:** upgrading infrastructure without capabilities breaks Helm-managed deployments and hides endpoints and metrics.
- **BWCE-11205 / BWCE-11181:** with IPv6 disabled the CP file server and BW web server fail to start; remove `listen [::]:8080;` from the tenant-integration-fileserver configmap.
- **PLTDX-1343:** Azure Files breaks the Developer Hub PostgreSQL pod; use Azure Disk.
- **PLTDX-911 / PLTDX-967:** a leftover `oauth2proxy` release blocks Developer Hub provisioning; `helm uninstall` it.

Closed in 1.20.0: PCP-23331 (CP logs stopped reaching Elasticsearch after the 1.19.0 upgrade) and PCP-20976 (BW6 agent auto-switching with NGINX ingress and NetScaler).

Review the complete official list before production upgrades: [Official 1.20.0 Known Issues](https://docs.tibco.com/pub/platform-cp/1.20.0/doc/html/Release-Notes/known-issues.htm).
